# momo B 題：Merchant Card Showroom 規格

2026-10-01 定案並完成本機功能實作；實際驗收結果列於本文，遠端交付待辦另列。套件與啟動見 [README](../README.md)，決策過程見 [協作紀錄](agent-collaboration.md)。

## 目標與範圍

以 Vue 3 + TypeScript，在最多兩小時的實作時間內完成商品卡展示、內容編輯、瀏覽器儲存與獨立 HTML 引用。依真實 momo 商品卡觀察選定一種版型，記錄簡化之處。

題目的「列出所有商品卡 / 展示單一商品卡」解讀為展示作品提供的版型：初版只有一種版型、一組示範資料及一個編輯區。

- **版型**是資訊排列與視覺結構；**商品卡**是套用版型呈現一筆商品資料的畫面。更換資料不代表增加版型。
- **草稿**是正在編輯的內容；**已儲存內容**是最後一次成功保存的快照，供重新開啟後還原。
- **Showroom** 是展示與編輯介面；**sample HTML** 是獨立引用範例，自行提供商品資料。

## 必做功能

| 功能 | 範圍 |
| --- | --- |
| 展示 | 一種固定版型、單卡預覽及一組初始示範資料。 |
| 編輯 | 商品名稱、圖片網址、售價、促銷標籤文字四個欄位；即時預覽，標籤留空即隱藏。 |
| 驗證 | 名稱非空白；售價為有限且不小於零的數字；圖片為有效 HTTP(S) 網址；文字按純文字呈現。 |
| 儲存 | 明確的儲存按鈕、未儲存提示、localStorage 持久化及重新載入；格式版本不列為編輯欄位。 |
| 失敗處理 | 失效圖片顯示佔位圖；驗證、儲存、讀取、資料格式與版本錯誤依下方驗收表處理。 |
| 獨立引用 | script 接收容器及商品資料，掛載／移除商品卡；sample HTML 使用正式建置的 JS 與 CSS。 |
| 交付 | 實站觀察、可重現建置、Git 歷史、Agent 協作紀錄及 README。 |

## 架構與資料流

| 部分 | 責任 |
| --- | --- |
| 商品卡 | 接收外部資料，呈現固定版型與失效圖片佔位圖；不取得商品資料、讀寫儲存或管理草稿。 |
| 編輯器 | 四個欄位、錯誤提示及儲存操作；將修改與操作交給 Showroom，不直接寫 localStorage。 |
| Showroom 狀態 | 管理單一草稿、已儲存快照、驗證、未儲存與操作結果提示；將草稿交給預覽。 |
| 儲存模組 | 封裝 localStorage 讀寫、資料格式／版本檢查及失敗結果。 |
| script 入口 | 接收容器、驗證外部資料、掛載及移除共用商品卡；不載入 Showroom 或它的儲存資料。 |

Showroom 載入示範值或已儲存內容後建立草稿。編輯器修改草稿，商品卡即時呈現；按儲存後依序驗證、寫入，成功才更新快照與成功狀態。失敗時保留草稿及原快照。

Showroom 與 sample HTML 共用同一份商品卡來源，各自帶入資料。修改 Showroom 售價只影響自己的資料；修改商品卡排版後，需重新打包並更新引用檔案，兩邊才使用新排版。

## 最小架構與測試範圍

以下依 codebase-design 與 tdd 整理，不增加必做功能；使用者已確認四個測試檔及其測試範圍，並確認採 useShowroom＋storage.ts，不加入 Pinia 或持久化插件。已加入 Vitest、Vue Test Utils、jsdom，完成 4 檔共 63 個測試案例。

```text
src/
  App.vue                     # Showroom 組裝與提示
  components/ProductCard.vue  # 共用商品卡，局部樣式
  components/ProductEditor.vue # 四欄位與更新／儲存事件
  composables/useShowroom.ts  # 草稿、快照、驗證與儲存流程
  configs/product.ts         # 示範值、儲存 key 與版本
  types/product.ts           # 資料、草稿、結果型別與所需 enum
  utils/product.ts           # 共用資料驗證與草稿轉換
  utils/storage.ts           # 讀寫、格式版本檢查與錯誤結果
  embed.ts                   # 獨立 script 掛載／移除
sample.html                  # 自行帶入資料，引用正式 JS／CSS
```

既有 main.ts、i18n 與 Showroom 樣式保留；根目錄另以 vite.embed.config.ts 設定嵌入產物，不建立通用建置框架。

- **資料持有者：** useShowroom 持有 draft 與 lastSaved，公開 patchDraft、save 與供畫面讀取的草稿、預覽、錯誤及狀態。編輯器透過事件提出修改，App 接線；商品卡只收呈現資料，僅保有圖片失敗等視覺狀態。
- **輸入中的無效值：** 草稿售價保留輸入文字；驗證通過才轉成數字寫入 Product。無效售價的預覽資料以 null 表示，由商品卡顯示佔位文字，避免空白轉成零。轉換集中在 utils/product.ts。
- **儲存：** 公開 load／save，回傳成功、無資料或明確失敗原因，將序列化與版本細節藏在模組內。useShowroom 只在寫入成功後更新 lastSaved；無資料或讀取失敗以示範值建立草稿，讀取失敗顯示警告且不回寫。lastSaved 與初始 dirty 比較基準分開，未曾儲存的示範資料不冒充已儲存內容。
- **測試 seam：** 儲存模組可接受提供 getItem／setItem 的來源；正式來源為瀏覽器 localStorage，測試來源可模擬拒絕讀寫。useShowroom 使用真實儲存模組，只透過這個外部依賴替換來源，不另建 repository 或依賴注入框架。
- **嵌入：** mountProductCard(container, data) 驗證外部 unknown 資料，失敗回傳錯誤，成功回傳 unmount。使用同一份 ProductCard，不載入 Showroom、儲存或全域 Tailwind reset；卡片採局部樣式，必要繁中文案隨嵌入產物提供。

資料流：編輯器事件 → patchDraft → 草稿／預覽 → 商品卡；儲存事件 → 驗證 → storage.save → 成功才更新快照。sample.html → embed.mountProductCard → 共用商品卡，資料由 sample 提供。

已確認自動化測試為 **4 個測試檔、12 組行為**；參數化案例會使實際測試數高於 12，不以測試數量作為驗收目標。

| 測試 seam／檔案 | 三組行為 | 對應規格 |
| --- | --- | --- |
| 資料驗證／utils/product.test.ts | 合法資料（含零售價、空標籤）；空白／負數／非數字／非有限售價；空白名稱、缺欄位與不合法 HTTP(S) 網址。 | AC06–08、AC19 |
| 儲存 load／save／utils/storage.test.ts | 無資料及寫入後讀回；壞 JSON、缺欄位、無效資料及未知版本可辨識且不覆寫；讀寫例外回傳失敗並保留原內容。 | AC10–11、AC14–16 |
| Showroom 公開狀態與操作／composables/useShowroom.test.ts | 初始還原或降級、修改立即預覽但重建仍讀到舊存檔；有效儲存後重建還原新資料並清除 dirty；無效或寫入失敗保留草稿與快照，解除失敗後可重試。 | AC01–04、AC06–08、AC10–16 |
| 嵌入公開掛載介面與 DOM／embed.test.ts | 有效掛載、移除與無效輸入拒絕；sample 資料不受 Showroom 儲存影響；商品卡純文字呈現、空標籤隱藏、無效售價佔位及圖片失敗佔位。卡片專屬情境直接透過其 props／DOM 測試，不放寬嵌入入口的資料驗證。 | AC04–05、AC07、AC09、AC18–20 |

第三組或第四組內不同結果各以獨立案例測試，不將全部分支塞入單一測試。商品卡 props／DOM 亦屬已確認 seam，與嵌入測試同檔以控制規模；不額外逐一測元件內部函式。

人工與交付檢查仍包含：四欄位接線與儲存操作、實際圖片 404、兩個正式頁面的 JS／CSS 載入及資料隔離、宿主樣式不受影響、實站觀察、乾淨安裝建置與文件／Git 歷史（AC01–26 按各條件記錄）。DOM 測試不能取代正式產物的瀏覽器驗收。

兩小時內先完成必要測試與主流程，測試隨功能逐步加入；不設覆蓋率門檻、不增加整套端對端平台，不測常數是否等於自己。選做 schema 只有主流程及必要驗收完成後才考慮，若要實作，再確認其測試 seam。

## 技術取捨與 Bonus

| 決策 | 原因與代價 |
| --- | --- |
| 一種版型、四欄位、固定樣式 | 把時間投入完整流程；不提供外觀客製化與多商品管理。 |
| 即時草稿＋明確儲存 | 避免輸入中途的無效內容覆蓋資料；需要草稿與快照兩份狀態，使用者須主動儲存。 |
| localStorage＋格式版本 | 適合小量瀏覽器資料；不做後端同步、跨分頁衝突合併或版本遷移。 |
| script 掛載共用元件 | 直接驗證獨立引用；產物包含 Vue 執行環境，沒有 Shadow DOM 隔離，需避免污染宿主樣式。 |
| 單頁及局部狀態 | 一個編輯流程即可完成需求；不加入路由或全域狀態套件。 |
| 先跑通 script 正式產物 | 優先排除嵌入與樣式的交付風險，再完成編輯儲存。 |

- **Reusable Card Architecture：必做成果。** 以獨立引用、資料獨立及共用來源檢查驗證（AC17、AC18、AC20）。
- **State Consistency Strategy：必做成果。** 驗證草稿、儲存及重新載入的一致性（AC10–AC16）。只涵蓋單頁情境。
- **Schema / Plugin Extensibility：選做。** 有餘裕才用簡單欄位描述產生四個編輯欄位。基本資料定義、執行時驗證與儲存版本仍需做，但不能僅憑型別／版本號宣稱此 Bonus 完成。

## 驗收

從 Showroom 的外部操作流程與獨立 HTML 驗證，檢查畫面、提示、儲存及重新載入結果，不綁定私有方法或內部變數。以 Vitest 驗證關鍵狀態，不要求覆蓋率數字。

測試準備：一組有效名稱、可載入的 HTTP(S) 圖片、售價 999 與促銷文字；只清空或修改作品自己的儲存項目。以請求攔截／測試服務模擬圖片 404，以儲存邊界替換模擬讀寫例外；不新增故障注入操作介面。正式產物透過本機 HTTP 服務開啟。

## 不做的項目

- 多商品管理／切換、多份草稿、切換確認；第二種版型及版型選擇系統。
- 字體、顏色、間距、主題、自由排版、圖片上傳。
- 自動儲存、草稿復原、離開確認；sample 與 Showroom 資料同步。
- 多分頁即時同步、衝突合併、版本遷移、完整 Plugin 註冊／動態載入。
- 真實商品後端串接、購物車、結帳、會員等商業流程。
- Web Component／Shadow DOM、file:// 雙擊開啟承諾、路由、全域狀態套件、大型測試框架或覆蓋率目標。
